## Outcome

7. Run independent code, browser, visual, interaction, accessibility, network, and performance review under CW-007.

## Minimal code-native geometry contract

### 1. Selected trace-panel metadata

Materialize exactly one compact metadata record per manifest asset after art QA. The art QA report remains the provenance source; the product table contains metadata only and never imports or fetches the PNG.

```ts
type SelectedTracePanel = Readonly<{
  assetId: CareerAssetId;
  panelId: `${CareerAssetId}#canonical-trace-v1`;
  sourceSha256: string;
}>;
```

Rules:

- The key set equals the 56 manifest IDs exactly.
- `sourceSha256` is copied from the promoted QA record without reinterpretation.
- `panelId` is stable for the asset version. Replacing the source image after a targeted retry requires a new source hash, renewed QA, and an explicit metadata update.
- Panel role, crop bounds, descriptor, QA outcome, and tracing notes remain in the promoted QA artifact; geometry workers read them there. Duplicating those strings into the client would add no runtime behavior.
- No output path, imported bitmap, base64 payload, pixel data, image dimensions, region descriptor, or reviewer note is needed by the client.
- A Node test reads the QA artifact from `docs/` and compares IDs and hashes. Product modules must not import from `docs/` or `design/`.

### 2. Projection

Use one exact projection record for every definition:

```ts
const CAREER_WORLD_PROJECTION = Object.freeze({
  id: "cw-iso-225-45-35.264-r0-v1",
  type: "orthographic-true-isometric",
  cameraAzimuthDegreesFromNorth: 225,
  lookDirectionDegreesFromNorth: 45,
  elevationDegrees: 35.264,
  rollDegrees: 0,
  authoredRotationAllowed: false,
  north: "+Y projects upper-left",
  screenX: "(x-y)*0.8660254",
  screenY: "-(x+y)*0.5-z",
} as const);
```

Projection helpers round generated SVG coordinates to four decimal places. Definitions store `projection: CAREER_WORLD_PROJECTION.id` and `orientation: 0`. No instance may override either value.

### 3. Geometry definition

```ts
type PaletteSlot =
  | "structure.base"
  | "structure.shadow"
  | "line.primary"
  | "line.secondary"
  | "accent.emissive"
  | "accent.focus"
  | "label.primary"
  | "terrain.claim";

type Footprint = Readonly<{
  width: number;
  depth: number;
}>;

type DetailTier = 0 | 1 | 2;

type GeometryPrimitive =
  | Readonly<{
      type: "surface";
      id: string;
      path: string;
      fill: PaletteSlot;
      stroke?: PaletteSlot;
      detailTier: DetailTier;
    }>
  | Readonly<{
      type: "extrusion";
      id: string;
      plan: readonly Readonly<{ x: number; y: number }>[];
      height: number;
      top: PaletteSlot;
      litSide: PaletteSlot;
      shadowSide: PaletteSlot;
      stroke: PaletteSlot;
      detailTier: DetailTier;
    }>
  | Readonly<{
      type: "stroke";
      id: string;
      path: string;
      stroke: PaletteSlot;
      detailTier: DetailTier;
    }>;

type GeometryDefinition = Readonly<{
  assetId: CareerAssetId;
  category: "world" | "city" | "project" | "skill" | "ambient";
  geometryKey: `career-world/${string}/master-v1`;
  masterGeometryHash: `sha256:${string}`;
  primaryPathHash: `sha256:${string}`;
  primaryPath: string;
  footprint: Footprint;
  orientation: 0;
  projection: "cw-iso-225-45-35.264-r0-v1";
  paletteSlots: readonly PaletteSlot[];
  primitives: readonly GeometryPrimitive[];
}>;
```

The footprint is a conservative, centered, projected ground envelope in the 1024 x 1024 employer-local placement frame. It is collision authority, not a value recovered from PNG pixels. The world definition uses the 1600 x 900 world frame; its footprint is the accepted world envelope.

`primaryPath` is the normalized outer silhouette path and remains rendered at every LOD. It must agree with the selected panel and manifest brief, but it is deliberately authored in code. Avoid automatic raster tracing and SVG boolean-geometry dependencies.

### 4. Three primitives only

The allowed primitive union is intentionally narrow:

- `surface`: irregular roof, pad, terrain, canopy, or silhouette-aligned face.
- `extrusion`: any prism, tower, pod, rail, ramp, bridge deck, cylinder approximation, or regular/irregular plan polygon with deterministic top and side faces.
- `stroke`: seams, rails, frames, interior conduits, and technical-cartography linework.

Small helpers may create rectangular or regular-polygon plan points and canonical path strings. Do not add a primitive because one asset has a named architectural feature. Add a fourth primitive only if at least three assigned assets cannot be represented without duplicating unstable path-generation logic, and stop for tech-lead review first.

This is 2.5D SVG path construction, not a scene graph, CAD system, WebGL renderer, or 3D engine.

### 5. Detail-tier rule

- Tier 0 contains the complete primary silhouette, all exterior masses, required connections, footprint-defining faces, and primary outline.
- Tiers 1 and 2 contain interior-only seams, windows, panels, rails, conduits, and restrained decorative marks.
- Hiding tier 1 or 2 must not change `primaryPath`, footprint, roofline, facade rhythm, sign-slot anchor, orientation, or projection.
- Every primitive remains in the definition and therefore in `masterGeometryHash`; semantic zoom changes only its visibility.
- Easter-egg detail remains illustrative, at most one active per project focus and three visible per viewport, and must fit inside the accepted silhouette/footprint contract.

### 6. Hash contract

Use SHA-256 over UTF-8 canonical payloads. Store the resulting values literally in each definition; do not ship browser crypto or compute identity hashes during render.

`primaryPathHash` hashes the exact canonical `primaryPath` string.

`masterGeometryHash` hashes one ordered JSON tuple containing:

```text
schema version
assetId
category
geometryKey
projection
orientation
footprint width and depth
exact eight palette-slot names in canonical order
primaryPath
ordered primitive payloads, including IDs and detail tiers
```

Exclude labels, source-panel metadata, source paths, employer palette values, instance ownership, positions, focus state, and current LOD visibility. Object-key sorting is unnecessary: the foundation owns one explicit tuple serializer. A Node test recomputes both hashes and fails on any literal mismatch.

### 7. Palette and reuse

Define five employer palettes plus neutral world and ambient palettes. Every palette fills all eight canonical slots. Geometry definitions contain slot names only; no definition contains an employer hex value.

- Each city and project instance receives its owning employer palette.
- All 27 skill assets have exactly one geometry definition each.
- All 37 employer-skill instances reference those 27 definitions and differ only by instance ID, employer ownership, fixed position, palette, focus/emphasis, and detail visibility.
- Do not clone or wrap skill geometry per employer.
- Java keeps its canonical definition and selected-panel metadata but remains without an instance until an approved mapping exists.
- Informatica, Atlassian, and CI/CD keep their employer-supported instances but gain no project link or factual claim.

### 8. Unique world, city, project, and ambient configurations

- The world has one unique code-native geography definition and the five accepted district anchors.
- The five cities each have one unique capital definition and one promoted CW-005C capital instance; P0 still owns the four pending positions and collision review of all five.
- The 16 projects each have a unique `geometryKey`, primary path, and master hash. The six ACE Hardware/Column Technologies projects remain identity-only illustrations with zero evidence trace and zero project-skill links.
- The seven ambient assets each have one unique definition and an explicit non-interactive, illustrative placement policy. Ambient instances are fixed only after roads and critical buildings; they never become required navigation or evidence.

No generic placeholder geometry may satisfy a missing asset. Shared primitives are required; shared final project/city/ambient silhouettes are not.

Add one pure `GeometryRenderer` that switches over the three primitive types. It receives a frozen definition, palette, and visible detail tier, always returns every primitive with a stable key and tier annotation, and changes visibility through attributes/classes. Keep it free of state, effects, image loading, network access, browser measurement, and asset-specific branches.

The scene maps all five capital, 16 project, and 37 skill-instance records on every render. `GeometryRenderer` is the only path from an asset definition to visible asset geometry. `world-scene.tsx` may compose stable groups, transforms, labels, and interaction-state classes, but it may not retain direct anchor-derived city diamonds, hard-coded project/skill rectangles, or asset-specific SVG geometry. ### Camera, bounds, and map gestures

The existing `WorldCamera` remains the only pan/zoom state. `world-camera.ts` owns pure, deterministic helpers for world/screen conversion, pointer-anchored zoom, screen-delta pan, clamping against fixed world bounds, and the CSS `matrix(a, b, c, d, e, f)` derived from camera plus viewport. These helpers accept data and return data; they do not read DOM, React state, media queries, or global events.

Apply that CSS matrix, with transform origin `(0, 0)`, to one stable inner SVG group. Do not transform or replace the outer SVG and do not create per-LOD camera groups. Under normal motion, the inner group has a nonzero computed transition duration, produces at least one sampled intermediate matrix distinct from both endpoints, reaches the exact pure-helper final matrix, and retains the same DOM node. Under `prefers-reduced-motion: reduce`, including a preference change while open, its computed duration is exactly zero without changing the target camera or available content.

The new `use-world-map-interactions.ts` hook owns only transient gesture mechanics and cleanup. It receives the map element/viewport, current camera, and a camera setter; it does not own semantic focus, drawer state, registry data, or geometry. Its contract is:

- ordinary wheel zoom is anchored to the pointer after converting the element-relative CSS-pixel location through the current viewport, then clamped to world bounds;
- `Ctrl`-wheel and `Meta`-wheel are returned to the browser unchanged: no `preventDefault`, camera change, or synthetic replacement;
- primary-pointer mouse, pen, and one-finger touch drag use pointer capture, update through the pure pan helper, and release on up, cancel, lost capture, unmount, or a second pointer;
- a named CSS-pixel drag threshold separates tap activation from pan, so a completed drag cannot activate the underlying city/project/skill control;
- browser pinch/page zoom remains available, controls do not require wheel or pinch, and document scroll outside the map is not intercepted.

Instance state may change only:

- role visibility appropriate to the semantic zoom band;
- interior detail tier;
- focus/emphasis classes;
- project-skill relationship highlighting;
- pointer-event availability for currently visible semantic targets.

It may not change asset ID, geometry key/hash, primary path/hash, footprint, orientation, projection, ownership, position, palette ownership, or DOM identity.
